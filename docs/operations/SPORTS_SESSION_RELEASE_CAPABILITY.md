# Sports session release capability

Authenticated live-session open returns `X-Atlas-Live-Release-Capability` alongside the existing session ID and TTL. The signed credential has a dedicated audience and kind and binds the exact Atlas user, session ID, target ID, and resource lease ID. It expires six hours after open, matching the playback gateway session's maximum lifetime. It is not renewed by heartbeat.

The Portal keeps this credential only in the in-memory session result. Every close, heartbeat-failure cleanup, cancelled open, replacement, and unmount carries the same session credential. It is sent in a request header to `DELETE /api/v1/sports/live/sessions/{session_id}/release-capability`; the token never enters a URL, local storage, or diagnostics. This cleanup path does not read or refresh the login session. Older session responses without the header continue to use the existing authenticated DELETE route.

The API checks signature, expiry, issuer, audience, kind, exact session scope, and the persisted user's target and lease linkage before any provider action. Reading that linkage does not prune an expired record. Cleanup still closes the owned stream first, then releases the session and linked resource lease. Uncertain stream closure returns 503 and retains the session and lease for reconciliation. Missing ownership returns 404 without provider actions. Repeated release cannot close another viewer's session. The credential cannot open playback, bootstrap a stream, authorize media, or renew a heartbeat.

A failed heartbeat displays “Atlas could not renew the live playback lease.” That message does not identify whether authentication, network, or server state caused the failure. Playback stalls and refresh-token behavior are unchanged by this review.

Do not paste the credential into logs, screenshots, tickets, or shell commands. Keep any failed-cleanup evidence private. A timeout or provider process observation alone does not authorize deleting shared ownership records. A token after six hours, an already-pruned session, browser termination before cleanup, or a partial durable-write failure can still require operator reconciliation. This change is explicit release authorization, not automatic stale-owner reclamation.

Validation covers a login-unavailable release after heartbeat expiry, preservation of the second shared viewer, exact target and lease binding, signature/expiry/audience/kind rejection, blocked close preservation, release replay, open response issuance, browser compatibility, validation-failure cleanup, and cancelled replacement. The CT100 review runner runs focused API tests, full Core/API/Portal suites, typecheck, and changed Portal lint. No production playback or recovery is performed by the review packet.
