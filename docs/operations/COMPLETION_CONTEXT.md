# Completion context equivalence

The historical private collector fingerprints the complete generation inventory,
including Python caches. A later fingerprint difference cannot renew an old
receipt or justify rewriting its sealed owner-preservation context.

This completion-only comparator requires all original context components except
the aggregate generation fingerprint to remain identical. A mandatory trusted
host callback must inspect the current generation against the retained source
archive, prepared provenance, operator environment and every compiled cache.
The callback runs even if the aggregate fingerprint matches and must return None
or refuse. Callback mutation, booleans and self-declared proof dictionaries refuse.

The callback belongs to a separately pinned host driver. It must establish real
filesystem and native provenance checks; fixture callbacks confer no production
authority. The comparator does not identify the cause of the old fingerprint
difference by itself, perform I/O, capture health gates, accept external evidence,
move a marker, clear a fence, or reopen maintenance.

A new completion-specific receipt must keep the historical context digest and
the freshly observed context digest distinct. Original private attempts, the
preservation plan and archive intent remain untouched. Fresh runtime/Doctor/Verify
and applicable external admission remain independent driver requirements.
